# Icon Forge

Маленький конвейер для иконок мест на карте.

Он не рисует иконки сам — он делает **приёмку**:

1. проверяет SVG по техническим правилам;
2. собирает манифест набора;
3. рендерит контактный лист в светлой и тёмной теме, в размерах 24 / 32 / 48 px
   и в круглом жетоне 76 px.

Так можно быстро отличить нормальную гравюрную иконку от залитого чёрного пятна.

## Интерфейс в браузере

```bash
npm run icons:ui
```

Откроется `http://localhost:5190` — простая студия:

- форма новой иконки: `id`, название, теги, уточнение и список того, что нельзя рисовать;
- кнопка «Сгенерировать»;
- кнопка «Все отсутствующие»;
- кнопки «Проверить SVG» и «Собрать превью» для всего набора;
- карточки иконок с размерами 24/32/48 и жетонами в светлой/тёмной теме;
- статус проверки и причины отказа;
- лог генерации;
- уточнение и перегенерация прямо в карточке иконки, скачивание SVG.

### Уточнение и повторная генерация

Модель склонна повторять один и тот же образ: на «таверну» она может упорно
рисовать кружку. Поэтому у каждой иконки есть два поля:

- **Уточнение** — что именно изобразить (например, «здание таверны: фасад,
  дверь, окно, вывеска на кронштейне»);
- **Не изображать** — что запрещено (например, «кружка, бокал, чашка»).

Поля сохраняются в `briefs.json` рядом с иконкой и передаются модели при каждой
генерации. Кнопка «Перегенерировать» каждый раз выбирает **новый
композиционный подход** из `directions.mjs` (фасад, разрез, вид сверху, силуэт
и т. д.) и поднимает температуру, поэтому результат не залипает на одном
силуэте. Кнопка «Сбросить историю» очищает список использованных подходов,
чтобы пройти круг заново.

`briefs.json` — локальный файл, он в `.gitignore`. Ключ DeepSeek читается
только сервером из `.env`. В браузер ключ не попадает.

## Команды

Из корня репозитория:

```bash
npm run icons:validate
npm run icons:preview
npm run icons:generate -- --id swamp
npm run icons:ui
```

`icons:validate` проверяет все файлы из `icons/`, сверяет их со `spec.json`
и обновляет `manifest.json`.

`icons:preview` собирает `preview/preview.png` — общий лист для просмотра.

`icons:generate` просит SVG у DeepSeek, проверяет его и только при успехе
сохраняет в `icons/`. Если модель нарисовала залитое пятно, иконка не попадёт
в набор.

## Генерация через DeepSeek

1. Скопируй `.env.example` в `.env`:
   ```bash
   cp tools/icon-forge/.env.example tools/icon-forge/.env
   ```
2. Открой `tools/icon-forge/.env` и вставь свой ключ:
   ```text
   DEEPSEEK_API_KEY=sk-...
   ```
   Ключ остаётся локально: `.env` в `.gitignore`. В чат его присылать не нужно.
3. Добавь будущую иконку в `spec.json`:
   ```json
   { "id": "swamp", "title": "Болото", "tags": ["swamp", "marsh"] }
   ```
4. Сгенерируй:
   ```bash
   npm run icons:generate -- --id swamp
   ```
   Или сгенерировать все отсутствующие:
   ```bash
   npm run icons:generate -- --all-missing
   ```
   Перезаписать существующую:
   ```bash
   npm run icons:generate -- --id forest --force
   ```
   Перерисовать с новой композицией и уточнением:
   ```bash
   npm run icons:generate -- --id tavern --variant \
     --brief "здание таверны: фасад, дверь, окно, вывеска на кронштейне" \
     --avoid "кружка, бокал, чашка"
   ```
5. Проверь и посмотри превью:
   ```bash
   npm run icons:validate
   npm run icons:preview
   ```

DeepSeek — текстовая модель, поэтому он не может сам посмотреть на
`preview.png` и сказать «иконка плохо читается». Визуальную приёмку пока
делает человек. При желании следующий шаг — подключить мультимодальную
модель для автоматической визуальной критики.


## Как добавить иконку

1. Добавь запись в `spec.json`:
   ```json
   { "id": "swamp", "title": "Болото", "tags": ["swamp", "marsh"] }
   ```
2. Положи SVG в `icons/swamp.svg`.
3. Запусти:
   ```bash
   npm run icons:validate
   npm run icons:preview
   ```
4. Посмотри `preview/preview.png`.
5. Если всё устраивает — коммить SVG и `manifest.json`.

## Требования к SVG

- `viewBox="0 0 24 24"`;
- `fill="none"`, `stroke="currentColor"`, `stroke-width="1.5"`;
- никаких заливок, текста, фонов, рамок, внешних ссылок и растровых картинок;
- отступы от краёв иконки;
- одинаковая оптическая плотность с соседями.

Полный стиль-гайд — в `style.md`.

## Где здесь «агент»

Сейчас это **детерминированная часть** агента: проверка и визуальный контроль.
Следующий слой — генератор:

```text
LLM → SVG → validate → render → визуальная критика → повтор
```

Генератор можно подключить к любому OpenAI-совместимому API. Важно, чтобы модель
умела писать код, а не только рисовать картинки. Ещё лучше — мультимодальная модель,
которой можно показать получившийся `preview.png`.

Пока иконки нарисованы вручную по `style.md`, но проходят через тот же контроль,
через который потом будет проходить работа модели.
